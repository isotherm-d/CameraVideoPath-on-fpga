# BitWriter PRG-8000：本机硬件服务端口被 Windows 保留

2026-10-13，TD 6.2.168116。BitWriter 日志连接 `127.0.0.1:5555` 后报 `PRG-8000 ERROR: Connect server failed.`。

## 实测原因与修复

- Windows IPv4/IPv6 TCP 保留范围包含 5502～5601，因此 5555 不允许绑定。
- .NET socket 实测：5555、5556 绑定失败，错误码 10013；6555 绑定成功。原来三个残留 hwserver 都没有 TCP 连接/监听，父进程已退出。已清理这些失效实例。
- 按默认端口重启时，hwserver 输出 `bind: No error`，没有监听；这行文字不表示启动成功。
- 已使用同一 TD 6.2 的 `hwserver.exe -r -f 12 -i 0 -s 6555` 启动隐藏后台服务，6555 监听和 TCP 连接检查均通过。没有修改系统保留端口、FPGA 源码或比特流，没有操作开发板下载。

## BitWriter 操作

在服务器设置（Server Setting）中把服务器地址设为 `127.0.0.1`，端口改成 `6555`，再连接。若使用 BitWriter Tcl Console，执行：

```tcl
connect_cable -host_name 127.0.0.1:6555
```

也可在 BitWriter 控制台 `source` [连接脚本](../tools/连接BitWriter6555.tcl)。该脚本只连接已启动的服务，不扫描 JTAG、不编程 SRAM、不写 Flash。不要给这条连接加 `-open`，它是启动服务选项，可能额外启动实例。

服务在退出或重启电脑后需重新启动；可从 PowerShell 使用：

```powershell
Start-Process -FilePath 'C:/Anlogic/TD_6.2.1_Engineer_6.2.168.116/bin/hwserver.exe' -ArgumentList '-r -f 12 -i 0 -s 6555' -WorkingDirectory 'C:/Anlogic/TD_6.2.1_Engineer_6.2.168.116/bin' -WindowStyle Hidden
```

已有服务时不需重复启动。若连接仍失败，先检查 6555 是否有监听和服务器地址是否仍为 5555，再查下载线选择/驱动，不需要重新综合 FPGA。

本地依据：`C:/Anlogic/TD_6.2.1_Engineer_6.2.168.116/bin/log/bw_2026-10-13_12-35-39.log`；诊断和服务日志在 `C:/Users/cqm87/Desktop/2026/tmp/bitwriter_server_20261013/`。官方说明见安装目录 `doc/Tools_UG/UG009_OneCable_User_Guide.pdf` 第 7～8 页：默认 RBB 5555 可更换，客户端设置同步更换。`-f` 是 JTAG MHz，`-i` 是 USB bus ID。
