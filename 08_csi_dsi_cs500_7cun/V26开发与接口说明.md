# V26 进阶任务与接口说明

基线 v25 的提交为 4795a67；开发分支 feature/task135。相机配置继续为 1280×720、30 fps，主像素处理时钟为 100MHz。v24/v25 标签与比特流保留。

## 功能和操作

模式 0～6：原图、灰度、二值化、Sobel 边缘、卡通、素描、复古暖色。卡通使用中值滤波、三位颜色量化与黑描边；素描为白底黑线；复古使用定点 sepia 矩阵。板载两个功能键分别切换下一个/上一个模式，SW1 保留复位。切换在帧首生效，状态文字属于同一帧。

双击 tools/打开收图窗口.bat，运行 cam_gui_v26.py。它需要与 v26 比特流配套；原 cam_gui.py 保留用于旧版本。收图 UDP6000，配置广播 UDP6001，状态/应答 UDP6002。网卡为 192.168.1.100/24，板端 192.168.1.66。

白平衡有标定预设、色温 K、手动 RGB、自动场景四种模式。预设继续使用 R344/G256/B451；K 表是近似光源曲线，6500K 只是参考锚点。自动模式统计中性候选，生成绝对增益并平滑、限幅；暗场、过曝或中性样本不足时冻结。自动模式不显示伪造的“测得色温”。

手动 RGB 范围 64～1024，Q8 的 256 表示 1 倍；自动范围 128～1024。拖动 RGB 会切换手动白平衡；拖动曝光或模拟增益会关闭自动曝光。曝光单位延续 v25 的半行编码和 62～1800 范围，增益档位 16～143 按 SC500GainTbl 编码。界面显示成功写入的曝光/增益，未声称已读回传感器寄存器；传感器生效可能延后。

AE 从白平衡后、风格化之前的图像测量亮度，目标 112、死区 ±8，每四帧评估；帧间设置稳定等待。偏暗先提高曝光，达到限位才加增益；偏亮先降低模拟增益以减小噪声，再降低曝光。I2C 初始化和运行期更新有单一请求/确认桥，写入中的数据保持不变，并上报 NACK/超时。

自动对比度只进入显示支路，是 32 箱分位点自动色阶，不是完整直方图均衡化。低跨度画面旁路，增益限制在 0.5～2 倍，避免放大暗场噪声。分类输入从此阶段之前取图。

保存键 s 保存 FPGA 输出的完整 RGB 帧，q/Esc 关闭。帧包含 FPGA OSD 时，保存图也有该文字；关闭 OSD 可保存净图。个人抓帧保存在 tools/captures，Git 忽略它。

## 公共像素流 CVP_PIXEL_V1

采用 valid 加固定 128 位像素字，时钟/复位单独传递。摄像头分支没有 ready，禁止任意反压。位置定义在 common/cvp_pixel_defs.vh：

| 位 | 内容 |
|---|---|
| 23:0 | RGB888，R 在高字节 |
| 35:24 / 47:36 | x / y，12 位零起始坐标 |
| 79:48 | 32 位采集帧身份 |
| 95:80 | 16 位配置号 |
| 103:96 | 8 位模式号 |
| 104 / 105 / 106 | SOF / EOL / EOF，与对应像素同拍 |
| 107 | 错误指示 |
| 108 / 109 / 111:110 | OSD / AE / WB 模式状态 |
| 127:112 | 预留，首版为零 |

每帧 921600 个有效像素、720 个行尾和一个帧尾。RGB 窗口边界复制，RAW Bayer 窗口反射以保持同色相位。右/下边界完整排空。内部 FIFO 按当前相机突发和消隐设计，超出容量会报告错误，不宣称能接任意无限连续速率。

cvp_style_stream 使用这个公共接口。cvp_pixel_delay 可以把整个像素字及 valid 延迟相同周期，支持 valid 的无效间隔。点运算的 RGB 延迟必须与其元数据一致；窗口算子的输出坐标必须代表实际窗口中心，不能直接复制输入槽位坐标。

扩展新算法时：

1. 实现同样的 clk/rst_n、i_valid/i_pixel、o_valid/o_pixel 端口，保证每拍最多一个像素且吞吐满足 30fps。
2. 在选择器里增加新模式，配置控制器的 MODE_COUNT 与 Python MODE_NAMES 同步增加。
3. 接入公共流，保留帧身份、配置号及边界标记，不修改网口帧格式和摄像头配置。
4. 用随机 valid 间隔、首末行/列、切换帧及像素参考模型验证。

## 给队友的细胞分类挂接

cvp_advanced.clean_valid/clean_pixel 是未风格化、未加对比度、无 OSD 的标准图像；其中模式号为 0。也提供 clean_rgb、x/y、SOF/EOL/EOF、frame_id、cfg_id 的拆分端口。图像已经过白平衡，训练和推理必须使用一致的成像/预处理约定。

在 design_top_wrapper 的 advanced 实例中，将目前留空的 clean_* 输出接到队友的 ROI 检测/裁剪模块。不要把分类模块的 ready 接回相机通路。

cvp_patch_bridge 是双完整图块缓冲。默认 32×32×1、unsigned GRAY8，每块 1024 字节、行优先。WIDTH/HEIGHT/CHANNELS/PIXEL_FORMAT 参数可调整；INT8 只是另一种字节含义，量化零点、缩放及饱和仍须按模型提供，不自动猜测。

描述信息含 frame_id、roi_id、cfg_id 和原图 bbox。i_sop/i_eop 随首末字节；i_valid/i_ready 是标准握手，忙时源须保持数据。对于不能等待的实时 ROI 产生器，应在图块开始前检查 ready，忙则跳过整块并自行计数，不能丢掉几字节后继续发送。桥仅在完整长度与 EOP 正确时交付图块，错误通过 dropped/protocol_error 返回。

推理结果接到 advanced 的 result_*：

- result_valid/result_ready；
- result_frame、result_roi、result_bbox，bbox 按四个 16 位 x0/y0/x1/y1 大端打包；
- result_class，8 位类别号；
- result_score，32 位有符号分值的位模式；
- result_format，0=原始 logit、1=margin、2=模型定义的概率格式；
- result_done_tick，100MHz 共同时间基准，0 时桥记录接收时刻。time_ticks 为可共享的计时输出。

不同钟域先使用 cvp_mailbox 或合适的 FIFO，不能只同步多位数据每一位。GUI 只在结果帧号与图像一致时叠加框和类别。分值不会自动被解释为概率。

当前结果输入接零，没有接入 LeNet 训练权重和真实推理核心。本次测试使用合成图块及模拟消费者验证双缓冲与反压。队友挂接前还需确认尺寸、通道、裁剪缩放、量化、类别表和结果格式。

## 控制协议

现有 v25 的 8 字节控制命令兼容。新控制包为 16 字节：
C5 A5 50 02 | request_id U16 | cfg_id U16 | op U8 | addr U8 | reserved U16 | value U32。全部大端。

op：1 SET，2 COMMIT，3 GET，4 时间同步。SET 写影子配置，COMMIT 在下一有效帧首整组生效。应答状态 0=已接受，1=待帧首，2=已生效，3=忙，4=拒绝，6=同步。重复 COMMIT 返回当前生效状态。GUI 串行等待应答并重发；超时不显示为成功。

| addr | 参数 |
|---|---|
| 0 | 展示模式 0～6 |
| 1 | AE 使能 |
| 2 | WB 模式：0预设、1K、2RGB、3自动 |
| 3 / 4 | 曝光半行码 / 模拟增益档 |
| 5 | 色温，单位100K |
| 6 / 7 / 8 | R/G/B Q8 增益 |
| 9 / 10 / 11 | R/B互换 / 对比度 / OSD |
| 12 | 二值阈值 |
| 13 / 14 | 弱边阈值预留 / 当前 Sobel 高阈值 |

首版 Sobel 为高阈值边缘，addr13 保留以便后续接弱边跟踪；GUI 不把它作为生效控件。

客户端使用独立的请求编号、检查应答接收时刻，COMMIT 后逐项 GET 核对实际值。完整事务最多重试三次；未核对通过不显示成功。

状态 UDP6002 保留 6 字节应用头，fmt=0x26；其后首 128 字节为 CV26/version1 状态，余下载荷补零。字段及顺序由 tools/v26_protocol.py 的 FIELDS 定义。现有图像头保持 frame_seq低8位、fmt1、offset U32，实际帧身份由源数据描述符传到 MAC，不用独立发送计数器猜测。

## 延迟口径

计时基准为 FPGA 100MHz、64 位计数器。采集起点是 RAW 组 FIFO 中帧首事件，不是未知的光学曝光起点。

- FPGA 帧首到处理首像素：包含窗口等待，使用同一帧事件。
- FPGA 帧首到最后包发送完成：按帧号匹配回传的 MAC 完成事件，跨域误差为少量时钟周期。
- PC 拼帧：首个有效包到完整帧，用 PC 单调时钟。
- 采集到首次显示提交估计：双向四时间戳映射后计算，显示 ±误差，失去同步时不填假数值。
- GUI 提交不等于显示面板真正发光；真实光学延迟仍需外部录像/光学测量。

协议中的处理/帧尾时间是相对采集时刻的32位周期差，正常远小于42秒；绝对采集、同步与快照用64位。GUI 重新构造绝对值。重复刷新同一帧不增加其“首次提交”延迟。

## 验证与构建

运行 tools/run_v26_regression.ps1 -OutputDir <临时路径> -Python <Python路径>。ModelSim 默认 C:/modeltech64_10.1c/win64；TD 默认 C:/Anlogic/TD_6.2.1_Engineer_6.2.168.116。参考激励由 generate_v26_vectors.py 生成。网络波形输出由 verify_v26_packets.py 使用 Python zlib 独立核对 Ethernet CRC、IPv4 校验和和 UDP 端口。

prepare_v26_build.py --name <新目录名> 在工作区 tmp/v26_task135 中创建隔离构建；不覆盖现有目录。使用随附 TD 模板生成 syn/phy 的 prj，分别执行 synthesis.tcl、physical.tcl。新代码注册到 GUI .al 时要保留明确的 CompileOrder。

硬件验证脚本 validate_v26_board.py --output <个人临时目录> --stress-seconds 1800 会修改运行期控制，测试七模式、手动增益、AWB、AE、对比度，再恢复预设与曝光500并做30分钟检查。运行前关闭其他收图程序。它仅保存本机场景图片，不上传。

最终布线时序、实际资源、比特流 SHA256 和实物记录位于 releases/v26。DSI 未列入本阶段验收范围。SRAM 下载断电后丢失，恢复 v25 使用 releases/v25/camera_to_dsi_display_v25.bit。

目前 SRAM 重载后需要短按 SW1 一次，再打开收图窗口；本次板测也执行了该复位。摄像头复位输出仍沿用原厂常高接法，热重载时可能记录启动阶段 NACK；复位后启动错误应清除。界面继续显示真实错误标记，不屏蔽它。

12 项新 RTL、10 项 v25 基线 RTL、27 项 Python 检查通过；另有独立 Ethernet CRC/IP/UDP 检查和隐藏 Tk 操作验证。布线 setup WNS 0.109ns、hold WNS 0.020ns，TNS 均为 0。Slice15410/21216（72.63%）、ERAM54/108、DSP10/40；Slice 超过尽量70%的软预算，后续模型挂接需重新布线验收。

两光源白平衡精度、AE明暗阶跃收敛、实体功能键仍需专门实测；当前记录不覆盖这些结果。队友最小端口映射见 V26队友挂接示例.md。
