# V25 校色与控制修复

当前阶段：工程修复、仿真和完整编译已完成；手机参考照片的配对实物校准待抓帧。候选比特流尚未下载到板上，v24 标签和比特流保留。

## 已完成的修复

1. Q8 增益改为 `round(pixel * gain / 256)`，保留溢出位后饱和到 255。256 为 1.0 倍，511 接近 2.0 倍；不再错误地除以 512。
2. GUI 直接按 RGB 显示，PNG 保存相同 RGB 数据；移除显示前多余的红蓝转换。
3. 控制 socket 显式启用 UDP 广播，发送失败会显示错误。“参数已发送”不代表板端已回读。
4. 白平衡模式明确为“标定预设、色温 K 值、手动 RGB”。拖 RGB 滑条自动进入手动 RGB，并发送色温 0，使三通道命令实际参与计算。R/B 互换在三种模式中都有效。
5. 色温曲线按真实的 14 个温度锚点插值，而非错误的段索引。离线按倒色温（mired）插值成 76 项、100 K 一档的 ROM，保留两拍流水；没有运行时除法或混用有符号数的插值。
6. 色温换算叠加相机参考场景的通道校准，预设与参考色温使用同一组增益，避免切换模式突然失去传感器白平衡补偿。临时参考增益为 R291/G256/B246，尚未用本次手机照片配对标定。
7. 旧 DPC 把 Bayer 红/蓝异色对角像素当成同色邻居。彩色平场仿真中 512 个正常像素有 202 个被误改。v25 保留原窗口与延迟、旁路替换判据，从而保留真实颜色。此版本暂不剔除孤立坏点。
8. 收齐整帧才发布到窗口，拒绝无效偏移、重复包及上一帧迟到包。帧率计数使用完整帧；complete 显示已接收帧的完整比例，不再显示当前帧的收包进度。

## 控件与命令

曝光保留 62～1800 半行的限幅。停止拖动 250 ms 后发送。启动窗口不自动改写曝光；“应用全部参数”可发送界面中的完整设置。

| GUI 模式 | 命令 | 板端行为 |
|---|---|---|
| 标定预设 | cmd6=1 | 使用曲线的参考校准点，不是实时场景 AWB |
| 色温 | cmd7=25..100，cmd6=0 | 色温×100 K；G=256，R/B 查传感器校准曲线 |
| 手动 RGB | cmd7=0，cmd2/3/4=增益，cmd6=0 | 采用三通道滑条，范围 64..511 |
| R/B 互换 | cmd5=0/1 | 所有模式生效 |

CLI 示例（先关闭其他控制程序）：

```powershell
python cam_ctrl.py exp 560
python cam_ctrl.py preset
python cam_ctrl.py kelvin 6500
python cam_ctrl.py gain 291 256 246
python cam_ctrl.py swap 0
```

控制包为 8 字节：魔数 4 字节、命令 1 字节、数值 3 字节大端。UDP 6001 为控制，6000 为图像。

## 手机照片的使用与待完成验证

参考照片：用户提供的 IMG_20261007_141523.jpg。需要保持摄像头、杯子、纸巾、红色物体及光线不变，用板端完整 RGB 帧选取对应区域，比较通道比例并校准 R/B 灵敏度。

旧窗口目前占用 UDP 6000，不能同时启动抓帧程序。关闭窗口后先抓 v24 基线，再将已通过时序检查的 v25 候选程序下载到 SRAM，抓取单位增益和校准后的图像。确认颜色及控制行为后再定版 v25 标签。

手机照片经过自身成像处理且视角不同；参考点用于本场景的色彩平衡，不是灯光色温的测量，也不能代替多光源色卡标定。曲线其他温度的响应目前沿用近似先验。

校准数据位于 `tools/wb_profile.json`；修改后运行 `python tools/generate_wb_lut.py` 并重新编译 FPGA。`--check` 可核对源代码与校准数据一致。
