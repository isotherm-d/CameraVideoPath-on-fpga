## 数据通路

```
SC500CS(MIPI 720p30 采窗1287x727) → csi/raw10解包 → uial2axis(IMG_H=720)
→ line_retimer(重切320拍x720行) → group_fifo(40.2M→100M跨域)
→ cvp_proc(齿轮箱+DPC+3x3 demosaic, 参数 IMG_W=1280/IMG_H=720)
→ color_correct(参数化白平衡: 标定R291/G256/B246 + 网络命令运行时覆盖)
→ pack_4(攒96bit) → cvp_eth_dbg(GMII 125M 展开, 1920包/帧)
→ RGMII → YT8531 → 网线 → PC (UDP 6000 视频 / 6001 命令)
                          ↘ cvp_proc 内 AE 参数通路 → uicfgcs500 → 传感器曝光寄存器
```

## 遗留问题(未解决, 按优先级)

1. **画面偏暗**: 720p30 曝光上限 33ms + 环境暗 → 需补光(推荐, 画质无损)。
   数字增益已满档(511/511/492), 模拟增益已顶(档 88)。AE 闭环已接通(mode=1 自动)。
2. **帧率实测波动**: 串口 CAM f=30 稳定, 但 UDP 抓帧曾测得 0.8~1.3fps ——
   **已定性为测量假象**(GUI 与诊断脚本同时绑 6000 端口, Windows 分流各收一半;
   "complete=50%"与"上下画面不同"均为分流+帧交界残留, 非 RTL bug)。
   **测量时必须先杀掉 GUI 进程再绑 6000**。
3. **GMII 展开器零裕量**: 30fps 需求 10.37M 组/s vs 能力 10.42M —— 理论上任何气泡
   即丢帧, 但实测 complete=100% 正常, 暂不动; 若未来偶发丢帧, 首选降帧率到 24fps
   (VTS 1280), 或展开器 12拍→10拍改造。

## 排查方法论记录（给后来者）

- **串口 CAM/ISP 双通道统计**（cam_stats x2 + cam_report_uart）: CAM=RAW 层,
  ISP=color_correct 前一层。f/p 读数是判定传感器/ISP 层是否正常的首选手段
  (p/f 应=230400 组/帧@720p)。
- **心跳 scan word**: cvp_cmd_rx 的 o_awb_en/o_kelvin 经 scan word 上报
  (字节序: 低8位在前)。注意 cmd 语义: 板上 cmd6=1 是自动 AWB 使能, 0=冻结;
  GUI 已做语义换算(修复于 be3b497)。
- **UDP 抓帧必须独占 6000**: GUI/脚本并存会分流产生假读数(0.8fps/50% 假象)。
- **Python 逐拍模拟**(tools/sim_v10.py 风格): 内容级校验(不只计数)曾抓出
  三次 RTL bug; 时钟比要真实(GMII:像素 = 3:1)。
- **TD 编译失败后必清 .al 的 AutoExcluded**: TD 自动排除出错文件并回写 .al,
  会连锁产生 black box; 修复代码后需 grep AutoExcluded 清零再重编译。
- **新增文件必须 Add Sources 或改 .al**: 否则 black box。
- **ae_set.v 等含中文的文件是 GBK 编码**: 编辑时用 gbk 读写, 用 utf-8 会损坏。
