# v37 候选：缩短 AE 收敛时间

## 控制变化

保留曝光优先分配、数字增益 1～4 倍、默认 Q10 系数 Kp=4/Ki=1/Kd=0、±8 亮度死区、高光保护目标和抗积分饱和。

- 先收集两帧新的有效统计；两帧平均与当前目标相差至少 24 个亮度码时立即调节。两帧不足以判定大误差时，继续收集到四帧，接近目标仍用四帧平均。
- **仅 FPGA 数字增益变化**：在 SOF 提交成功后不再丢弃两帧，直接统计这个完整新帧。最早在两个新帧后再次调节。
- **传感器曝光变化及手动提交**：仍丢弃两帧。I2C ACK 只确认寄存器写入，SC500CS 0x3800=0x40 按传感器帧内指定时刻生效；当前没有把实际曝光帧号反馈到控制器。PID 本身不能消除这段执行器延迟。
- 保留请求确认和互斥；失败写入不提交积分，空统计清除部分窗口，禁止使用未确认参数继续调节。原生 CSI 帧边界、短帧残尾丢弃、group hold 写表不变。

30 fps 下，曝光大误差阶段的等待/采样从 2+4 帧缩短为 2+2 帧；纯数字增益大误差阶段从 2+4 帧缩短为 0+2 帧。这些数字不含请求提交/I2C/下一个 SOF 的时间。

## 与 v36 的闭环对比

冻结 v36 原 AE 控制器，并核对其原始 SHA256 与 v36 发布清单一致。[独立闭环模型](tb_v26_ae_fast.log)分别驱动新旧控制器：写入确认需两个帧事件，曝光确认后还允许两帧旧光学反馈；纯数字增益在确认帧首生效。下表是首次进入目标 ±8 的帧数，场景及执行器一致。

| 场景 | v36 帧数 | v37 帧数 | 时间减少 |
|---|---:|---:|---:|
| dark | 49 | 41 | 16.3% |
| bright | 49 | 41 | 16.3% |
| very_dark | 95 | 63 | 33.7% |
| recovery | 65 | 45 | 30.8% |

暗/亮/数字增益均衡后各观察 100 帧，未继续发调节请求；±6 交替噪声与 80/144 交替亮度无调节。测试覆盖空统计、失败恢复、待确认互斥、24 码快慢边界、曝光确认后旧亮度被丢弃和数字增益确认后无盲等。

[高反差模型](tb_v26_ae_contrast.log)稳定窗口内当前仍为 0 次调节，v35 为 15 次；保护目标仍为 83、均值 87。这个模型中加速没有重新引入目标与高光争夺导致的振荡。

[真实 RTL 视频链路模型](tb_v26_pid_pipeline.log)运行 460 帧，检查 sensor bridge、SOF 数字增益、RGB 统计、曝光优先和连续帧输出；帧号/长度正确、没有黑帧和流错误。模型验证不等同于实机的曝光响应/噪声验证。
