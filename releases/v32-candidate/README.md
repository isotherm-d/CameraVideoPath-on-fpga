# v32 候选：AE 四帧平均与小步长调节

基于用户确认上板功能无误的 v31。AE 改为四帧分组平均，减小曝光和模拟增益步长；本候选已仿真、综合布线。随后用户上板报告有帧率但黑屏：截图显示平均亮度 137、传感器正常、累计流错误 2；已定位旧图像核心的流错误标志永久锁存，并被上位机用于将画面置黑。修复候选和诊断见 `../v33-candidate/README.md`。

## 行为

- 每四个连续、非空的有效统计帧做一次判断，亮度以四帧均值判断，亮度目标区间仍为 104～120。高亮比例以四帧累计高亮数 / 累计采样数判断，阈值仍为超过 5%。分组平均不需要像素帧缓存，也不增加除法器。
- 曝光每次增减 `max(1, exposure >> 5)` 半行，约 3.125%；原来为约 12.5%。例如 500 → 515，而非 500 → 562。曝光范围仍为 62～1800 半行。
- 模拟增益每次增减 2 档，原来为 8 档；范围仍为 16～143 档。避免低增益区一次跳 25% 跨过整个亮度稳定区间。
- 每次请求后，等待传感器桥接器结束忙状态，再丢弃两帧有效统计，之后收集新的四帧。关闭 AE、相机未就绪、传感器忙或空统计帧会清空未完成的平均窗口。
- 初次有效判断需四帧；持续调整通常至少间隔六个可用帧，30 fps 下约 200 ms，另加写入和帧对齐时间。光照突变时会比 v31 收敛慢。
- 上电默认曝光 500 半行、增益 108 档；AE 默认关闭，由上位机开启。传感器寄存器表、I2C 写入协议、亮度阈值及其他图像功能沿用 v31。本次没有加入照明周期防频闪约束。

## 仿真验证

28 项 RTL 回归及两组独立网络包 CRC/IP/UDP 校验全部通过；中值、风格、对比度、RAW 旁路的已有冻结基准差分也通过。AE 行为是有意改变的，因此不要求 AE 输出逐拍等同于 v31。

新增 `tb_v26_ae_smooth` 通过 33 项检查：四帧平均、交替亮度抑制、分数均值阈值、短暂/持续高亮、32 位计数累加无溢出、忙状态和写后等待、空统计、关闭/重新开启、曝光/增益步长及上下限。

使用独立静态线性传感器模型比较冻结 v31 和新版：

- 固定光照、曝光 1800、增益从 16 档启动：120 帧内旧版调整 30 次并在 16/24 档间振荡，新版调整 1 次到 18 档、均值 106 后保持。
- 固定光照、增益 16、曝光从 500 启动：旧版一步到 562；新版分两步到 531，均值 106 后保持。确认曝光小步长仍能收敛。

这些模型验证控制逻辑，不替代真实传感器的曝光生效延迟、噪声和灯光条件。原 AE 源码冻结于 `tools/sim/gold_v31/`，还原模块名后的哈希与 v31 manifest 一致。
