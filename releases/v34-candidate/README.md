# v34 候选：曝光优先的帧级 PID 与数字增益

AE 先调传感器曝光到 62～1800 半行；曝光达到 1800 后才使用全局数字增益 1～4 倍。场景变亮时先退数字增益到 1 倍，再降低曝光。模拟增益保持用户设定值，默认 108 档，本次不自动调模拟增益。数字增益并入原白平衡乘法，保留像素流水延迟、风格模式、网络输出及 v33 流错误恢复。

## 控制参数

- 完整固定点 PID，默认使用 PI：`cvp_advanced` 参数 `AE_KP_Q10=4, AE_KI_Q10=1, AE_KD_Q10=0`，再传入控制器。D 对测量值作差并以 1/2 滤波，支持编译期启用；本比特流 D=0，避免亮度噪声引起跳动。非默认 D 的功能另有仿真，修改系数后须重新检查时序和实机响应。
- 目标亮度 112，104～120 内保持参数并清积分。保留四个有效新帧平均；成功写入并在 SOF 提交数字增益后，丢弃两个有效帧再收集四帧。四帧总高光比例超过 5% 时优先降亮度。
- 控制总量 `U=曝光×数字增益_Q8`。相对修正为 `(Kp×误差+Ki×积分+Kd×测量差)/1024`，按一次有效控制更新计时；积分限幅 ±128 个亮度码。亮度误差绝对值 ≥24 时单次相对步长限 25%，其余限 6.25%，有最小可表示调节量。限速、上下限及反向时抑制积分累积。
- 曝光变化才触发 I2C。成功 ACK 后在帧起始提交配套数字增益；写失败不提交增益或积分。请求序号防止旧写失败误取消后来参数相同的手动请求。手动设置优先，并在成功写入后的 SOF 将数字增益恢复为 1 倍。单独关闭 AE 会保持当前曝光和数字增益，手动应用设置可恢复数字增益。
- 上位机区分“模拟增益”和“AE 数字增益”。沿用 V27 状态扩展保留区，原协议字段与长度不变，旧客户端仍能收图。

## 验证

35 项 RTL、两组网络包完整性校验、37 项 Python 测试通过，日志保存在本目录。

- 独立光照/曝光模型、两帧执行延迟：暗场默认控制器 47 帧进入目标区，冻结 v33 为 255 帧；亮场 47 帧；极暗场 95 帧，曝光 1800、数字增益 3 倍。这是模型结果，实机收敛速度尚待验证。
- 实际配置→统计→PID→跨时钟 I2C→帧边界增益→完整图像链路：460 帧、58880 像素、17 次曝光写入通过；暗/极暗/亮场分别 36/47/66 帧首次进入目标区，模拟增益始终 108，流错误为零。
- 增益独立标量检查 100001 个样本，其中 25075 个 1 倍数字增益样本与冻结 v33 逐拍一致；覆盖四舍五入、饱和、R/B 互换、空拍及复位。
- 覆盖边界、死区、交替亮度、多帧平均、写失败、手动覆盖及相同曝光值的新旧请求交叠。D=2、D=32 的控制器测试亦通过。旧 AE 测试明确运行冻结基准，新 PID 单独验证；不宣称改变后的 AE 行为与原版等价。
