# v38 候选：PID 参数 6 / 3 / 1

按用户要求，把默认 Q10 系数从 Kp=4、Ki=1、Kd=0 改为 **Kp=6、Ki=3、Kd=1**。控制器和上层 `cvp_advanced` 默认值同步修改；顶层没有另行覆盖。这三个数字仍是 Q10 编码，实际系数分别为 6/1024、3/1024、1/1024，不是浮点 6、3、1。

微分项不再为零，沿用既有“测量微分”与一阶滤波：本次 raw D = 上次窗口均值 − 当前窗口均值，filtered D = (上次 D + raw D)/2。目标值变化不直接注入微分冲击。误差反向时清除积分与 D 历史；微分可暂缓调节，但不能让输出逆着当前误差调节。

[v37 的加速机制](../v37-candidate/README.md)保持：大误差两帧平均、接近目标四帧平均、纯 FPGA 数字增益提交后取消两帧等待、传感器曝光变化/手动提交保留两帧保护。曝光优先、模拟增益保持手动值、曝光 62～1800、数字增益 Q8 256～1024、±8 死区、高光保护目标和步长限幅均保持。

## 闭环验证

冻结 v37 4/1/0 控制器，核对原始源码 SHA256 与发布清单一致。新旧控制器使用同一个独立执行器模型：写入确认需两帧事件；曝光 ACK 后仍允许两帧旧光学反馈，纯数字增益在确认帧首生效。记录首次进入目标 ±8 的帧数。[日志](tb_v26_ae_fast.log)

| 场景 | v37 4/1/0 | v38 6/3/1 |
|---|---:|---:|
| dark | 41 | 41 |
| bright | 41 | 31 |
| very_dark | 63 | 65 |
| recovery | 45 | 37 |

6/3/1 并不保证所有场景都更快：亮场和暗转亮更快，暗场相同，极暗场略慢。调节次数和最终落点会受积分、测量微分、步长限幅及死区共同影响。回归不再断言每个场景必须比 4/1/0 更快，而要求暗/亮场 100 帧内、极暗场 160 帧内收敛，并保留同条件帧数报告和稳定性断言。

暗/亮/数字增益均衡后各观察 100 帧，未继续发调节请求。±6 交替噪声与 80/144 交替亮度无调节。23 个控制检查还覆盖失败恢复、空统计、确认互斥、快慢窗口边界、曝光旧反馈丢弃及数字增益无盲等。[高反差模型](tb_v26_ae_contrast.log)稳定窗口仍为 0 次调节。460 帧[完整视频 RTL 链路](tb_v26_pid_pipeline.log)检查帧序/长度、非黑输出、流健康和曝光/增益分配通过。
