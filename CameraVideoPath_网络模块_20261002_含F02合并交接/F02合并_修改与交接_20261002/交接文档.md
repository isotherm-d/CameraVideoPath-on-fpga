## 2. 做了什么、为什么(按时间线)

1. **合并网络模块**到米联客 08_csi_dsi 摄像头例程(队长指令:让智谱合进去做后端输出)。
2. **修 bug(关键)**:`cvp_gmii_mac_tx.v` 的帧内包序计数器 `r_pkt_seq` 原为固定 11 位(720p 遗留,最大 2047);1080p 每帧 4320 包导致帧尾判断 `r_pkt_seq == PKTS_PER_FRAME-1` 永不成立 → 帧号不递增、包偏移只覆盖前 2.9MB 循环 → PC 永远拼不齐帧(现象:心跳正常但 no video stream)。已改为 `$clog2(PKTS_PER_FRAME)` 自适应位宽。
3. **新增 `cvp_rgb_stream_pack.v`**:把 ISP AWB 输出的 96bit(4 像素/拍)转成 cvp_eth_dbg 要的单像素流。第一版吞吐不足,内部 FIFO 打满后按固定节奏丢拍 → 画面被横向压缩到 1/3 再平铺 3 遍(当时截图的"三原色方块");已改为预取+无空泡流水(持续 1 像素/周期 > 输入峰值)。中途还踩了一次 HDL-8007 多驱动(见 §4)。
4. **新增 `pll_gmii125.v` + wrapper**:25M→125M GMII 时钟,PLL IP 拷贝自米联客 rgmii 例程并重命名(避免与工程内 PLL.v 大小写/模块名冲突)。
5. **isp_top.v 两处**:demosaic/awb 例化参数 1024×600 → 1920×1080(旧小屏遗留,行缓冲宽度不匹配导致整幅行错位剪切,即第一版"黑白三角条纹"的成因);新增 AWB 96bit 观测输出端口(纯增量,原通路零改动)。
6. **SDC**:网口 125M 时钟加入 set_clock_groups 异步组(跨域全部走 Gray FIFO/双拍同步,否则时序分析报 ~-0.3ns 伪违例)。
7. **诊断旗标**:`i_dbg_flags` 接 4 个粘滞观测点(相机 I2C 配置完成/AWB 观测口有数据/转换器发像素/像素非全零),PC 心跳状态页可直接看——这是现成的远程仪表盘,后续调试优先用它。
8. **串口体检共存**:J3 脚 115200 每秒打印 `CAM t=1234567890 f=.. p=.. nz=.. sum=..`(t 为自检值),与网口互不干扰。

## 4. 踩坑记录(务必读)

1. **TD 开着会覆写 .al**:TD 用内存态回写工程文件,外部改的源登记会被冲掉。顺序必须是:改文件 → 关 TD → 重开工程。源文件(.v/.adc/.sdc)不会被覆写。
2. **HDL-8007**:同一寄存器只能在唯一 always 块赋值;合并逻辑时注意。
3. **PowerShell `Set-Content -Encoding UTF8` 带 BOM**,TD 可能不接受 → 用 `[System.IO.File]::WriteAllText($f,$t,(New-Object System.Text.UTF8Encoding($false)))`。
4. 本机**没有** 7z/WinRAR/iverilog;RAR 用系统自带 `tar -xf` 可解;Verilog 语法只能靠 TD 编译验证(没有本地仿真器,本次 3 个 bug 都是编译/上板才暴露的)。
5. **cvp_async_fifo 满后静默丢拍**,且节奏固定 → 症状是画面等比压缩平铺(不是花屏)。发送端吞吐必须 ≥ 输入峰值,否则必踩。
6. **GEN_TESTPAT 彩条发生器有 720p 硬编码**:色条边界写死 1120/1280 宽、`r_tpy` 只有 10 位(1080 行会回卷)。IMG 设 1920×1080 时测试图案本身会横向平铺、纵向在 1024 行处跳变——只影响测试图案观感,不影响用它验证链路(本次已用)。
7. PC 端 opencv 必须装**非 headless** 版(否则 namedWindow 报 not implemented);脚本需在 tools 目录下运行。
8. AQ: 以太网调试期间 PC 网卡静态 IP 192.168.1.100/24 + 关防火墙;板不实现 ARP/ping 不通是正常的。
