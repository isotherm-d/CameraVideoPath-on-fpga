# v35 候选：PID 组合路径分段

本次仅修改 `advanced/cvp_ae_control.v`。保持 v34 的 PI 默认参数（Kp=4、Ki=1、Kd=0，Q10）、四帧平均、两帧等待、曝光优先、1～4 倍数字增益、积分保护及写入/帧边界提交规则。

原路径从亮度误差依次穿过反向判定、积分加法/限幅、PID 项相加和修正限幅，进入乘法器数据与使能；增加 MEASURE/HISTORY/ACCUM/LIMITS/TERMS/SUM/CLAMP 七个寄存阶段，保留有符号位宽、算术右移及原 32bit 中间值规则。每次计算多 7 个 100MHz 时钟，即 70ns，帧级采样与收敛结果保持一致；请求时刻和计算 busy 标志持续时间相应变化。

## 布线结果

相同 PH1P35MDG324、TD 6.2.168116、100MHz 图像处理时钟；SDC 和布局布线设置与 v34 相同，未放宽约束。

| 指标 | v34 | v35 | 变化 |
|---|---:|---:|---:|
| Setup WNS | +0.015ns | +0.114ns | +0.099ns |
| Setup / Hold TNS | 0 / 0 | 0 / 0 | 无违例 |
| Hold WNS | +0.022ns | +0.020ns | 仍满足 |
| Slice | 10650（50.20%） | 10524（49.60%） | -126 |
| LUT6 | 8551 | 8533 | -18 |
| FF | 10674 | 10787 | +113 |
| ERAM / DSP / PLL | 49 / 15 / 2 | 49 / 15 / 2 | 不变 |

只读导入两版路由 DB、按同一端点集合另行检查：**AE DSP 数据/使能端点**（`get_pins {advanced/ae/mult*.y* advanced/ae/mult*.ce*}`，两版各 80 pins）的最坏建立裕量由 +0.015ns 提高到 +3.596ns；**AE 命名寄存器端点**（`get_regs {advanced/ae/*}`）由 +0.026ns 提高到 +3.187ns。这是两种明确的筛选范围，不把 DSP 端点值当作整个 PID 或整个工程的裕量。[旧 DSP 路径](v34_ae_dsp_endpoints.timing)、[新 DSP 路径](v35_ae_dsp_endpoints.timing)、[新寄存器端点](v35_ae_internal.timing)。STA 只读取 DB，未重新布线或修改 DB。

全工程最紧路径已从 PID 转到风格队列/控制到 tone RGB 的路径。寄存器增加但布线后 Slice 减少，来自组合逻辑缩短与综合/打包结果；不能将其概括为加流水必然节省 Slice。[全时序报告](timing_report.txt)、[资源报告](resource_report.txt)。

## 验证

- **36 项 RTL、2 组网络包完整性、37 项 Python 测试全部通过**。当前 187 个 HDL 与实际主工程构建 SHA256 一致；与 v34 相比只有 AE 控制器文件改变。
- 冻结 v34 控制器仅重命名模块，恢复名字后的原始字节 SHA256 与发布 manifest 一致。新旧差分 **84537 项检查、1199 条配对请求**，覆盖默认 D=0、D=2、D=32、signed16 正负极值及混合系数；比较请求 E/DG/AG 及有效的已提交积分、导数、误差和限幅状态，允许七拍计算延迟。
- 210 次新增状态优先事件覆盖取消、禁用、未就绪、忙和手动提交；180 次写失败覆盖失败后不提交历史。晚取消时 v34 可能已发出更早的请求，测试不给旧请求反馈，复位共同历史后再比较四帧新采样，不声称请求周期完全一致。
- 原控制器测试默认暗/亮/极暗收敛仍为 47/47/95 帧；D=2 与 D=32 的结果与 v34 保持一致。实际配置→统计→PID→传感器桥→SOF 增益→视频链路仍通过 460 帧。图像、模式、帧同步和网络回归均通过。
