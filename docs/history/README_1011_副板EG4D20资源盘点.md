## 一、v28 实测占用与余量

| 资源 | 器件总量 | 已用（v28 门级实测） | 利用率 | 余量 |
|---|---|---|---|---|
| LUT | 19,600 | 7,556 | 38.9% | **12,044（61%）** |
| BRAM（EBR） | 64 | 44 | 68.8% | 20 块 |
| DSP | 29 | 1 | 3.4% | 28 |
| **PLL** | **4** | **4** | **100%** | **0 —— 满** |
| DDR1 带宽 | 600 MB/s | 331.8（写 110.6 + 读 221.2） | 55% | ~268 MB/s |
| DDR1 容量 | 16 MB | 12.6（三缓冲 720p） | 79% | 3.4 MB |
| FF | — | v28 README 未记录 | — | 需队长 TD 报告补 |

用途分解（队长预算口径）：LUT ≈ 协议栈 4K + DDR 链 3K + HDMI 2K +
重组器 1K ≈ 10K 预算（实测 7.6k 更省）。

## 二、关键事实

1. **logo OSD 已经在 v28 里了**：右上角安路 logo OSD（16384×9b EBR
   位图，落点账本仿真逐像素 diff=0，上板显示正常）——"OSD 叠加 logo"
   原计划已落地，不是待办。
2. **PLL 4/4 满**：任何新增功能需要新时钟时必须复用现有 PLL 输出
   （HDMI 75MHz / DDR PLL / 网口时钟），这是副板扩功能的第一硬约束。
3. BRAM 余 20 块、DSP 余 28——充裕；LUT 余 12k——比主板目前的
   slice 缺口还大。

## 三、战略备注（供讨论，非决定）

主板 detect 全链 ≈9.2k LUT + 7.3k FF 是 129% 超限的主角；副板余量
12k LUT 恰好装得下。副板收到的 RGMII 镜像流本就是 AWB 后 RGB 帧
（与 clean 流同源），且已有 OSD 基础设施（logo 位图+落点机制）可
扩展画框——"检测搬到副板"在资源上成立。需队长评估的代价：副板
无以太网发送路径（纯二层接收），框数据上不了 PC GUI；BBR/EBR 还
要放检测链的行缓存与 scratch。此项与主板方案 C 并行评估。
