### 回收期间修复的三个真缺陷（都已在 9f0f32d 内，勿回退）

1. **水位播种**：帧首像素是背景时无人分配，r_alloc 停 0，首个 bump 分配取
   到保留号 0（=LNULL）→ line_lab 写 LNULL 断链、游程碎裂。修复=帧首像素
   无条件播种 r_alloc<=1。**旧代码那行 `else if (r_fst1) r_alloc<=1` 是护
   栏不是补丁，删前必须懂它**；
2. **被吸收标签 line_lab 幽影**：合并行上被吸收方的游程前缀仍以旧号写入
   line_lab、下一行才读掉——lasty 必须连被吸收方一起刷到合并行（关闭推迟
   到 +2 行），否则回收后旧引用接进新组件；
3. **父指针一拍竞态（焊接根因）**：游程第二像素的 S2 在第一像素 S3 自父
   指针写回**前一拍**执行 find3(r_run)，回收标签此刻 parent[] 还是上一世
   的父链 → 游程整体延长进已死组件并连锁焊接（4485px 巨框实证）。修复=
   **parent 写集中到 S2 判定拍**（分配自指/合并指向均提前一拍，顺带满足
   单驱动纪律）。旧代码单调分配下 parent[id] 未用前=id，此竞态潜伏不可见。

## 3. 综合受阻：323% 爆片，根因=LUTRAM 推断失败

- 实测（TD 6.2.1 DefaultFlow，syn_1 本地）：gate **68,634 slice=323%**，
  place **32,198=151.8%** 失败（PHY-9053）；det_wbc20 LUT 11k→**25.9k**，
  dram lut 2728→**1584**；
- **根因**：回收要求关闭组件统计存独立槽位 → COPY/burst 对 scratch 的写

  点+多地址寄存器"的阵列拒绝推断 LUTRAM** → scratch 七数组 256×92b 全部
  落成纯 LUT mux；
- **诊断实验**：临时屏蔽 burst 的 scratch 写 → dram lut 恢复 2736、gate
  降到 129% → 阻塞点确认；
