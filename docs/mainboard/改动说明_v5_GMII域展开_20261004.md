# v5 修正说明 —— 字节展开搬到 GMII 域(架构性修复)

日期:2026-10-04 | 基线:git v4 | 状态:模拟验证通过,待编译上板

## v4 上板结果(为什么还要改)

抓包解剖: 每帧 1280/1280 包**完整零重复**、帧间隔 211/241ms 交替(~4.4fps)、
内容可辨但撕裂(GUI 显示的 66.7%/1.5fps 是脚本统计口径, 实际帧是完整的)。
撕裂 = 每个网帧的内容横跨 ~4.4 个传感器帧(时间混叠)。

## 根因(v4 修复的架构缺陷)

S_csi_rx_clk 实测 **40.2MHz**(= 321.6Mbps/lane ÷ 8; 2-lane 数据以 16bit/拍
补带宽, 不是我 v4 假设的 80.4MHz)。v4 把"3 拍/像素字节展开"放在像素域:
每行 1024 像素需 3072 个字节拍(76.4us) > 行周期 44.4us —— **物理不可能实时**。
pack FIFO 长期满静默丢像素 → 字节数凑满(帧"完整")但内容跨帧。

## v5 架构

```
像素流(40.2M, 每拍1像素) → 24bit x 2048 像素跨域 FIFO(新增)
  → [GMII 125M] 3拍/像素字节展开(新流水) → 8bit FIFO(同域弹性, 原 IP 复用)
  → GMAC(不变) → RGMII → PC
```

- pack 回退为每拍 1 像素(v3 版, 40.2MHz 下 57% 占空比, 安全);
- 字节展开/帧字节计数/信用/跳帧全部搬 GMII 域: 能力 41.7MB/s > 需求 36.9MB/s;
- 帧尾字节恰为某像素的 B 字节(1,843,200 是 3 的倍数) → 跨帧相位天然对齐,
  **不清 bsel/run**(v5 开发中曾犯此错会致每帧丢 1 像素, 已在模拟中排除);
- 彩条发生器回退每拍 1 像素(与真实流同构)。

## 验证(Python 逐拍模拟, 含 FIFO 一拍读延迟, 供给率比真实激进 3 倍)

- 3 个帧尾的字节位置: 0 / 1,843,200 / 3,686,400(分毫不差);
- 两帧窗口 3,686,400 字节与期望字节流**零失配、零丢失、零错位**;
- begin/end 栈配对、信号声明、多驱动(HDL-8007)检查全部通过。

## 预期(编译下载后)

1024×600 **@20fps**、无撕裂、帧完整 100%。串口 f≈20 不变。
