# v7 修正说明 —— pack 双读覆盖 bug(吞吐恒减半的真正根因)

日期:2026-10-04 | 基线:git v6 | 状态:模拟 100% 验证,待编译上板

## 定位链(v6 双通道体检立功)

v6 串口读数: CAM p=3,072,000 且 **ISP p=3,072,000** —— RAW 层与 AWB 观测口
都满速, ISP 内部无减半; 而网口实测 10.7fps(需 20), 且该 50.2% 跨 v3/v5/v6
三代架构恒定不变 => 病灶锁定在 pack 一个模块内。

## 根因(一行代码的时序 bug, v1 交接版即存在)

pack 的读请求 r_pop 置位条件 (!r_next_v && !w_fifo_valid && !w_fifo_empty):
rd_en 发出后的下一拍, 预取槽尚未被回填(r_next_v 仍 0), 条件依然成立 =>
**连续两拍发出读请求**; 回填分支 (b) 无条件写 r_next => 第二个数据把第一个
**覆盖丢弃**。每读两拍丢一拍 => 输出恒为输入的 50%, 与三代实测 50.2% 吻合。
彩条模式下同样丢一半(彩条内容无感), 故当年彩条验证未暴露。

## 修复

r_pop 置位条件增加 (!r_pop): 每次读请求后至少间隔一拍, 单读节律,
回填链与装载链时序不变。修复后逐拍模拟(严格 RTL 寄存器语义 + 行突发时序):
输入 51,200 拍 = 204,800 像素, 输出 204,800 像素, **吞吐 100.00%**。

展开)/v7(双读) 四个独立 bug 全部修复, 网口链路首次以设计速率运行。
