# v3 修正说明 —— 从 720p30 回退到 1024x600@20fps(厂验配置)

日期:2026-10-04 | 基线:git v2 | 状态:代码完成,待编译上板验证

## v2 上板结果(为什么回退)

v2(1280x720@30)上板后 PC 端抓帧分析:
- 帧完整(1920/1920 包)、零丢包 → FPGA 链路和网口配置正常;
- 但帧率恒定 0.61fps(帧周期 1.63s 极稳),画面为斜条纹(行宽错位剪切)。

## 根因(两个,均已查实)

1. **开机曝光非法(主因,厂商例程潜在 bug)**:uicfgcs500 写完主表后必续写 AE 表,
   曝光 = I_AE<<4 半行。ae_set.v 的 I_AE 初值 3000 → 曝光 48000 半行 = 24000 行,
   是数据手册上限(2*VTS-10)的 32 倍 → 帧周期被曝光拉长到秒级、画面饱和。
   v2 把 VTS 改 760 后雪上加霜;v1(1080p) 时代同样中招(旧 bit 心跳 8 分钟无视频)。
2. **采窗寄存器 0x3200~0x3207 无文档**:数据手册只定义 0x3208/a(输出宽高)与
   0x3210~13(输出起始,默认 8,8)。v2 对无文档采窗寄存器的 7 处改动未被传感器
   正确接受,输出行宽与 1280 不符 → 斜条纹。

## v3 改动

| design_top_wrapper.v | uial2axis 1024x600;rgb_frame_crop 参数 IN=OUT(纯直通);cvp_eth_dbg 1024x600, FRAME_SKIP=1 |

## 结果指标

- 传感器输出 1024x600(= DSI 屏原生分辨率,显示全屏无裁剪),约 **20fps**(VTS 1127 厂验值);
- 网口 1280 包/帧,约 310Mbps,余量充足;PC 收图:`python eth_video_rx.py --width 1024 --height 600`;
- 串口体检照旧;预期串口 f≈20。

## 720p30 还有可能吗(后续)

需要传感器支持 1280x720 窗口 + VTS 760 + 曝光 ≤755 行三者同时成立。数据手册只给了
0x3208~0x3213 的语义(输出窗口),无文档的 0x3200~0x3207(采像窗口)是唯一能把
帧窗口缩到 727 行的途径,v2 已证明盲调有风险。若必须 720p30,下一步应:
1. 先在 v3 基础上只动 0x320e/f(VTS 760)+ AE 初值 93(=1488 半行=744 行),
   采窗保持 1024x600 不动 → 验证"小 VTS + 小曝光"能否 30fps(画面仍 1024x600);
2. 再逐步尝试采窗寄存器。每步一次上板,一次只动一个变量。
