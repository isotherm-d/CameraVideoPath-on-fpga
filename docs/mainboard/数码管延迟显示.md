# 数码管显示采集到网口发送完成的延迟

MLKPAI-F02主板的8位共阳数码管从左到右为：五位延迟、两位空白、一位实际图像模式0～6。延迟单位为毫秒、保留三位小数；延迟24.053 ms、模式3时显示 `24.053  3`，小数点不占数字位。延迟高位空白，整数部分至少保留一位，有效显示范围0～99.999 ms；超出显示范围、启动后或超过1秒没有新的有效测量时，左侧显示五条横线，中间两位保持空白，模式位仍保留。延迟每200 ms最多更新一次，避免数字快速跳动。

KEY3按一次模式递增，顺序为0→1→2→3→4→5→6→0；KEY2按一次模式递减，顺序为0→6→5→4→3→2→1→0。按键消抖后每次按下只切换一次，配置在视频帧首生效，模式数字随该帧完成更新。

| 最右一位 | 图像模式 |
| --- | --- |
| 0 | 原图 |
| 1 | 灰度 |
| 2 | 二值化 |
| 3 | 边缘 |
| 4 | 卡通 |
| 5 | 素描 |
| 6 | 复古暖色 |

模式取自最近完成的视频帧，与视频状态中的实际模式一致；待提交而尚未作用于视频的设置不会提前改变数码管。模式位在每轮1 ms扫描时采样，不受延迟200 ms刷新周期限制。模式位不点亮小数点；延迟的小数点随左侧的毫秒个位显示。

## 计时范围

起点是当前帧首组RAW10数据通过 `camera_group_valid && camera_group_sof`，进入ISP的时刻。终点是同一帧最后一个视频UDP包完成发送的MAC事件 `net_tx_done`。帧号使用清洁RGB像素流的真实帧号，分别保存完整帧号与采集时间；只接受匹配的发送完成事件，拒绝旧帧覆盖、重复事件、缺少起点和过期测量。

计时使用主板100 MHz计数器。125 MHz网口事件经过握手邮箱进入100 MHz域，计量中包括不足0.1 us的跨域通知延迟；MAC事件与RGMII物理引脚之间也存在数拍输出流水线差异。数码管按微秒截断换算，再以毫秒显示。它反映采集、ISP/叠加、排队和网口整帧发送的耗时，不包含传感器曝光之前的等待、网线传播、PC接收拼帧、HDMI显示子板或显示器刷新延迟。

YOLO采用独立的15 Hz推理支路。数码管测量的是30 fps视频帧的发送延迟，不是神经网络推理延迟。

## 接线和实现

引脚依据F02开发平台硬件手册第16节及厂商 `17_spi_hc595` 例程：

| 顶层输出 | FPGA引脚 | 板上信号 |
| --- | --- | --- |
| `O_seg_sclk` | C11 | 595_SFCLK |
| `O_seg_latch` | B11 | 595_LACH |
| `O_seg_data` | E8 | 595_DATA |

使用3.3 V电平。串行发送顺序为位选字节、段码字节，每字节高位先发，16位发送结束后锁存。位选高有效、段码低有效，段码bit7控制小数点。根据实板显示方向反馈，右端数码管位选为0x80，左端为0x01。扫描从右端的模式位开始，随后两位输出空白，再依次输出延迟的最低有效数字到高位；延迟按从左到右的方向阅读。KEY2连接 `I_button[0]`（N2），KEY3连接 `I_button[1]`（J14）。

`common/cvp_latency_display.v` 只观测现有视频和发送事件，不向采集、图像处理或发送链路施加反压。通过逐位除法和二进制转BCD完成换算，不使用组合除法器；数码管每位扫描周期125 us，一轮1 ms。整轮扫描锁存同一数值，避免跨次测量混字。主工程已加入源文件及三根输出的引脚约束。

## 验证

运行 `python hardware/mainboard/tools/test_latency_display.py`，独立核对：

- 异步时钟下的帧号与采集时间绑定、计数器和帧号回绕。
- 整数除法、小数截断、BCD转换，包含24.053 ms显示样例。
- 环形记录覆盖、重复发送事件、缺少采集起点及过期测量。
- 74HC595引脚实际串行输出：每16个移位时钟锁存一次、字节与位顺序、数码管段码、小数点、前导零空白和整轮扫描一致性。
- 最右模式位0～6、非法模式显示横线、无有效延迟时仍保留模式，以及模式改变时整轮显示的一致性。
- 五位延迟、两位始终空白的物理位置，0.000、0.001、99.999 ms边界，以及100 ms和更大值显示横线而不截断高位。

完整视频回归中的 `tb_v26_display_mode.v` 通过实际配置提交及图像处理/OSD链路检查所有七种模式和回到模式0，确认模式输出随视频帧完成更新；同时从物理按键输入分别检查KEY3递增、KEY2递减及6/0之间的回绕。`tb_v26_keys.v` 检查KEY2/KEY3方向、消抖和按住不重复。

测试输出在 `yolo/tmp/latency_display_20261022/`。最终物理实现和实板显示验收应分别记录；通过RTL仿真不等同于数码管实物显示已验收。
