# V26 分类模块挂接示例

本页用于对接队友模块。当前发布程序只提供接口，未包含细胞检测、裁剪缩放、模型权重或 LeNet 推理。请先确认模型尺寸、灰度公式、量化零点/比例、类别表和分值格式。

## 1. 从标准图像取数据

在 `design_top_wrapper.v` 的 `cvp_advanced advanced` 例化处，把目前留空的端口接到声明好的同名 wire：

```verilog
.clean_valid(clean_valid), .clean_pixel(clean_pixel),
.clean_rgb(clean_rgb), .clean_x(clean_x), .clean_y(clean_y),
.clean_sof(clean_sof), .clean_eol(clean_eol), .clean_eof(clean_eof),
.clean_frame_id(clean_frame_id), .clean_cfg_id(clean_cfg_id),
.time_ticks(time_ticks)
```

位宽：`clean_pixel` 128 位，RGB 24 位，x/y 各 12 位，frame_id 32 位，cfg_id 16 位，time_ticks 64 位，其余各 1 位。时钟为 `S_100m_clk`，低有效复位为 `S_rst_n`。这些端口来自同一条像素流，可以选择使用打包字或者拆分端口。

将它们送入队友的 ROI 检测/裁剪/缩放模块。它必须持续接收有效图像，不能通过 ready 停住摄像头。图像已做白平衡，未经过风格化、自动对比度和文字叠加。

## 2. 在 ROI 输出与推理入口之间放双缓冲

下面是 `cvp_patch_bridge` 的实际端口映射片段。`roi_*` 由队友的预处理模块提供，`nn_*` 接推理入口；这些 wire 和队友模块需在挂接时另行声明、例化。

```verilog
cvp_patch_bridge #(
 .WIDTH(32), .HEIGHT(32), .CHANNELS(1), .PIXEL_FORMAT(0)
) patch_buffer (
 .clk(S_100m_clk), .rst_n(S_rst_n),
 .i_valid(roi_valid), .i_ready(roi_ready), .i_data(roi_data),
 .i_sop(roi_sop), .i_eop(roi_eop),
 .i_frame_id(roi_frame_id), .i_roi_id(roi_id),
 .i_cfg_id(roi_cfg_id), .i_bbox(roi_bbox),
 .o_valid(nn_valid), .o_ready(nn_ready), .o_data(nn_data),
 .o_sop(nn_sop), .o_eop(nn_eop),
 .o_frame_id(nn_frame_id), .o_roi_id(nn_roi_id),
 .o_cfg_id(nn_cfg_id), .o_bbox(nn_bbox),
 .o_width(nn_width), .o_height(nn_height),
 .o_channels(nn_channels), .o_format(nn_format),
 .dropped(patch_dropped), .protocol_error(patch_protocol_error)
);
```

端口宽度：data/channels/format 为 8 位，width/height/roi_id/cfg_id 为 16 位，frame_id/dropped 为 32 位，bbox 为 64 位，握手和边界信号各 1 位。默认格式 0 表示 unsigned GRAY8，每块 1024 字节，逐行从左到右。

只有 valid 与 ready 同时为高才传递一个字节；等待时保持 data、SOP/EOP 和描述信息。SOP 伴随第 0 字节，EOP 伴随第 1023 字节，不能多发或少发。实时 ROI 生成器若不能等待，应在整块开始前检查 ready：忙则跳过整块，并在生成器中记录跳过次数。桥不会阻塞主图像，也不会替上游统计未发送的图块。

`bbox={x0,y0,x1,y1}`，每项 16 位，坐标属于原始 1280×720 图像。推理模块必须保留首字节携带的 frame_id/roi_id/bbox；不要使用推理结束时最新的摄像头帧号。

## 3. 把结果返回 advanced

将 `advanced` 原来接常量零的 result 输入替换为队友结果信号：

```verilog
.result_valid(nn_result_valid), .result_ready(nn_result_ready),
.result_frame(nn_result_frame), .result_roi(nn_result_roi),
.result_bbox(nn_result_bbox), .result_class(nn_result_class),
.result_score(nn_result_score), .result_format(nn_result_format),
.result_done_tick(nn_result_done_tick)
```

frame 32 位、roi 16 位、bbox 64 位、class 8 位、score 32 位、format 7 位、done_tick 64 位。valid 保持到 ready 确认。format：0 原始 logit，1 margin，2 模型定义的概率格式；必须在团队协议中说明尺度。done_tick 使用共同的 100MHz 时间基准，填 0 时由接收方记录接收时刻。

GUI 按原帧号匹配结果，迟到结果不会画到另一帧上。若推理延迟超过图像的显示等待时间，结果可能没有对应的当前画面；后续需要缓存显示帧或增加独立结果历史面板，不能篡改结果帧号。

## 4. 对接检查顺序

1. 先用 `tools/sim/tb_v26_patch.v` 的合成字节流检查顺序、SOP/EOP 和反压。此用例已验证五块数据和间歇 ready。
2. 接入 ROI 生成器，逐块对比 PC 上的预处理输出与 FPGA 字节；未通过前不接真实模型。
3. 接入推理核心，先使用固定样本核对类别和原始分值，再启用实时摄像头。
4. 加入不同模块时钟域时，使用握手 mailbox 或异步 FIFO；跨域前后同时保持描述信息和数据一致。
5. 重新综合、布局布线及板测。当前图像工程用了 54/108 块 ERAM、10/40 个 DSP、15410/21216 个 Slice；剩余资源不等于模型一定能通过时序。

这些片段展示对接位置和真实端口名，并不是可独立运行的分类工程。完整协议见 `V26开发与接口说明.md`。
