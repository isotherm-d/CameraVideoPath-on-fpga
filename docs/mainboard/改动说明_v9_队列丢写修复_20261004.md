# v9 修正说明 —— v8 预取队列"一进一出拍丢写入"bug

日期:2026-10-04 | 基线:git v8 | 状态:内容级模拟 100%, 待编译上板

## v8 上板现象(比 v7 更差的原因)

帧率 11.5 -> 2.0fps, 像素错位随机化(相邻行对齐移位 ±30 随机抖动)。

## 根因(v8 我自己引入, 一行条件错误)

预取队列的入队写条件误写成 (w_pxf_valid && !q_take): 同拍"一进一出"
(队列消费与 FIFO 到达同拍发生, 连续流下高频)时新数据未写入队尾, 但
q_cnt 保持不变 -> 队列内容错乱(垃圾/陈旧数据被当有效), 字节流内容
随机错 -> 图像随机错位; 展开器时序被垃圾数据打乱 -> 帧率崩到 2fps。
教训: v8 的模拟只验证了吞吐数量(计数闭环), 未验证内容 -> 假阳性。
v8 上板代价换来的收获: 模拟必须做字节级/像素级内容校验。

## 修复

入队写去掉 !q_take 条件(一进一出拍也必须写)。队尾 = 旧rp+旧cnt,
与同拍出队(rp 推进)不冲突。

## 验证(保守 FIFO + 突发写供给逐拍模拟, 内容级)

输出 614,400 像素与输入序列 0..614,399 逐一比对, 失配 0 处。
(吞吐 100% x 内容 100%, 双指标。)
