# V29 资源优化（功能与接口不变）

基线 v27（标签 524238b 方案同源）。目标：为 LeNet 分类核心腾挪资源，全部为纯资源优化，
七模式、AE/AWB、UDP 6000/6001/6002 三口、按键、OSD、标定 R344/G256/B451 与分类挂接接口
保持不变。**唯一功能变化：串口不再打印 CAM/ISP 诊断行**（该信息由 UDP 状态包覆盖，见文末）。

## 优化一：cvp_frame_stats 直方图 LUTRAM 化

原实现：32bin x 20bit 亮度直方图用触发器阵列逐像素自增，EOF 时整体拷贝到 snap 阵列再走查。
代价是 stats 模块 1129 个进位 LUT、80 个 F7mux、40 个 F8mux 全部来自这 1280 个 FF 的
读增写。改后：单端口分布式 RAM（异步读+同步写，地址 = y[7:3]），走查期（state==1）用
idx 直接读 bin，不再需要 snap 拷贝；EOF→走查起始的 1 拍间隙用 r_armed 屏蔽清扫防误清。

**新约定（重要）**：RAM 无法靠复位清零，改为"旋转清扫"——除法等待态（state 2/3/4，
约 120 拍）和上电空转期每次清 1 个 bin，任何路径下 32 拍内全零。因此：
- 实机无影响（摄像头启动门控到首帧是秒级）；
- **仿真 TB 必须在复位释放后空等 >=40 拍再驱首帧**（tb_v26_stats/tb_v26_advanced/
  tb_v27_awb 已各加 400ns 稳定期；新写 TB 时注意）。

## 优化二：状态跨域链 ERAM 化（cvp_status_bridge）

原实现：advanced 侧拼好的 1536bit 状态字经 cvp_mailbox（held+m_data 两份）传到 GMII 域，
mac_tx 再整份锁存进 status_packet——三份 1536bit 寄存器约 4600 FF，只为每 0.5s 发一个
1446B 状态包。改后：捕获拍把状态字按 16bit 字序列化写入双 bank ERAM（96 拍），mac 发送期
逐字读出，两级流水对齐保持消费拍与原 status_index/status_octet 一致。

**线上字节序（与原实现位精确，勿改）**：前 128 字节 = 向量低 1024bit 大端在前；之后 =
高位扩展区（V27! 段）大端在前。这是原 status_index[7] 分区逻辑的语义，不是整条向量平面
大端——差分测试曾在此抓出错位（DW=1024 时两种序恰好等价，1536 时才分裂）。

**工程注意**：cvp_status_bridge 模块已并入 cvp_eth_dbg.v 文件尾部，原独立文件
net/cvp_status_bridge.v 仅留注释占位。原因：TD 对"非 GUI 导入的新增文件"的 AutoExcluded
状态会在每次保存时反复，导致 cvp_eth_dbg 例化报 black box；并入既有文件后与工程文件列表
解耦。日后要拆回独立文件，必须先在 GUI 里 Add Source 正式导入。

## 优化三：元数据 FIFO 寄存器化（cvp_style / cvp_contour）

帧原子字段（帧号/配置号/模式/阈值）原本用 cvp_sync_fifo 跨越窗口流水延迟——其中 cvp_style
的 16 深队列被综合成 2 块 ERAM20K。改后：单 pend 寄存器 + pend_v 标志，SOF 拍写入、窗口
首拍消费；pend_v 复现原 FIFO 的"满/空"溢出检查语义（连续 SOF 未消费→overflow）。
消隐远大于流水深度（2~3 拍），队列不可能积压，语义等价由差分测试证明。

## 优化四：数据通路摘异步复位（cvp_style/cvp_contour/cvp_window3x3）

全设计原统一 `always @(posedge clk or negedge rst_n)`，纯数据打拍寄存器（bypass/sepia/xy/
mp 延迟链、128bit 像素令牌、window3x3 行窗口 a0..b2/c1/c2/prev2，合计约 1700 FF）也带
异步复位。异步复位 FF 与无复位 FF 控制集不同、不能共享 slice。改后数据链摘复位，
valid/sof/eol、状态机、坐标、增益累加全部保留复位。正确性依据：数据链与流水严格对齐，
首个有效像素到达前各级恰好写满；window3x3 的行缓存 RAM 读口本就无复位，首帧头部窗口
内容两类实现同为旧数据。**收益实测仅 -47 slice**——该设计打包的主导约束是各异的时钟
使能（CE），不是复位；此结论记录在案，后续若继续压 slice 应做 CE 规整化而非扩大摘复位范围。

## 优化五：移除 UART 诊断链（唯一的动能取舍）

design_top_wrapper 移除 u_cam_stats / u_cam_stats_isp / cam_report_uart 三实例（-1337 FF）。
O_uart_tx 常 1（空闲电平），顶层端口与 .adc 引脚约束不变。cam_stats.v / cam_report_uart.v
文件保留在磁盘（TD 自动排除不占资源），要恢复把实例贴回即可。

**串口诊断的替代**：UDP 6002 状态包（GUI 状态面板 / capture_now.py）——帧计数 last_fid、
组数 samples、流错误 stream_errors、I2C 诊断、AWB 状态与增益、延迟计量均在，且每 0.5s
一包信息量大于串口每秒两行。原"CAM 正常而 ISP 异常→ISP 链路问题"的分层判据，等价改为
"GUI 能收图=全链路健康；收不到图+状态包正常=查 PC 侧端口占用（先杀 GUI 再绑 6000）"。

## 验证方法与状态

- **差分测试（本次新增的方法论）**：gold 基准（改动前 RTL，tools/sim/gold_a/）与新实现
  同激励对照，逐拍比对全部输出端口。tb_a_diff_stats（17 帧随机场景，覆盖首帧黑/白点、
  valid 断流、AWB 冻结/恢复）、tb_a_diff_style（14 帧 128k 采样点）、tb_a_status_bridge/
  tb_a_status_wire（字节序/ping-pong/线上包 CRC）。全套 22 项回归（v26 12 + v27 6 + 差分 4）
  全过，记录在 old/releases/v29/rtl-tests.log。
- 过程中修掉 4 个真 bug：桥 request 翻转时机（序列化未完成即被读）、RAM 寻址空间错位
  （DW=1024 读 X）、状态字节序分区理解错误、cvp_frame_stats clr 多驱动（TD 检出）。
- **板级**：A/B 类比特上板确认（收图/状态回读/模式轮换正常）；v29 发布比特含 C 类
  （仅移除串口路径），综合布线 0 错误，上板复验后补记。
- **未重跑**（状态同 v27）：300s 压力轮换、两光源/色卡 AWB 精度、Flash 冷启动、实体模式键。
