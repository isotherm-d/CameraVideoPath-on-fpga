## 1. 系统总览

系统为**双板架构**：主板完成成像、检测、分类、叠加与发送，子板只做显示回显。

```
 SC500CS MIPI          主板 PH1P35 (MLKPAI-F02)                PC / 子板
┌───────────┐   ┌──────────────────────────────┐   ┌──────────────────────┐
│ 720p@30fps│   │ MIPI RX → ISP → YOLO 推理     │   │ PC GUI：收图/发参数   │
│ 显微摄像头 ├──►│ (RAW10→RGB) (160×160,15Hz)    ├──►│ (ETHA, UDP 6000/6001)│
└───────────┘   │ → 跟踪/框+文字叠加 → UDP 打包  │   │ 子板 EG4D20:         │
                │ ETHB = 发送镜像               │   │ 收流→DDR三缓冲→HDMI  │
                └──────────────────────────────┘   │ 720p60 + logo (ETHB) │
                                                   └──────────────────────┘
```

- **检测与分类在板内**：160×160 全帧 YOLO-style 单尺度检测器，五分类
  （Basophil / Eosinophil / Lymphocyte / Monocyte / Neutrophil），15Hz 推理、
  30fps 视频、单目标框 + 英文全称标签。
- **PC 只收图与下发相机参数**（UDP 6001 命令），不做任何识别/补画。
- 主板工程入口：`hardware/mainboard/td_project/camera_to_dsi_display.al`
  （TD 6.2.168116，器件 PH1P35MDG324）；候选 bit 在
  `hardware/mainboard/reports/yolo_wbc_bccd15/current/physical/`。

## 2. 主板数据流（模块级）

全部路径见 `hardware/mainboard/user_source/hdl_source/design_top_wrapper.v`（527 行）。

| 段 | 模块链 | 说明 |
|---|---|---|
| ① 成像输入 | `mipi_dphy_rx_ph1p_mipiio_wrapper` → `csi_unpacket_2lane` → `raw10_unpacket_2lane` → `uial2axis` → `line_retimer` → `group_fifo` | 2-lane DPHY 收 RAW10；`line_retimer` 强制按 320 拍×720 行重切时序；`group_fifo` 完成 CSI 字节域(~40.2M)→100M 主域跨域 |
| ② 启动门 | `cvp_camera_gate` | 等相机 I2C 配置完成 + AE 收敛后才开始放行有效帧（消上电动乱帧） |
| ③ ISP | `cvp_proc`（RAW10 解包+双线性 demosaic）→ `cvp_dpc` 坏点 → `cvp_awb` 三模式白平衡 → `cvp_ae` → `color_correct`/`wb_kelvin` 色温 LUT | 自研 ISP（非米联客 uiisp_beta，旧版仅留档）；输出 RGB888 30fps |
| ④ 场景控制 | `cvp_advanced`（V27 共享处理核） | AE 帧事件 PID（曝光优先+数字增益）、风格/边缘/素描、帧统计、配置/状态总线；输出 adv 流 + clean 抽头 |
| ⑤ **检测推理** | `cvp_yolo160_detector`（FRAME_INTERVAL=2）→ 内部 `yolo160_first`→`yolo160_core`→`yolo160_boxes` 三级 | 见第 3 节；100M 域，15Hz |
| ⑥ 跟踪与标签 | `cvp_yolo_tracks`（内含 `cvp_cell_tracks` 轨迹槽）→ `cvp_cell_label` | 类别绑定跟踪、漏检保持；5×7 点阵字模画框+英文全称，SW1 按键开关 |
| ⑦ 网络发送 | `pack_4`（RGB888→96bit）→ `cvp_eth_dbg` → RGMII TX | UDP 192.168.1.66→192.168.1.100:6000，1920 包/帧@30fps；ETHA 发 PC、ETHB 镜像给子板 |
| ⑧ 命令接收 | `cvp_cmd_rx`（RGMII RX 域解析） | UDP 6001 曝光/白平衡/增益命令 + 6002 状态回传 |

本地 DDR→DSI 显示支路自 **v30 起裁掉**（背光关闭），这就是主板能腾出资源的根源。

## 3. WBCAtt+ 检测与五分类（当前主线）

### 3.1 训练侧（yolo/wbc_bccd/）

- **模型**：自研、面向 RTL 实现的单尺度 YOLO-style 检测器（非 YOLOv5/v8 移植）。
  10 层：L1-L3 为 3×3 卷积+pool 下采样（160→80→40→20），L4-L6 在 10×10 上堆通道
  （16→24→40→80），L7-L8 为 1×1 降/升维，L9 输出头 40→30 通道
  （3 anchor × [x,y,w,h,obj,5类]），10×10 网格、anchor 边长 20/40/80。
  Conv+BN 权重折叠；"WBCAtt+"是数据集与训练轮次的命名，RTL 中无注意力模块。
- **两源联合训练**：WBCAtt 自建数据（TRAIN 6021 原图+6020 负裁图）+ BCCD 公开集
  （205 WBC 框，类别置 -1 屏蔽分类损失，只学定位）。
- **量化与导出**：FP32 120 轮 + QAT 80 轮（含 60 轮低照增强、40 轮 objectness-only
  滤波器微调）→ `quantized.npz` → `yolo/export.py` 打包 ROM hex → RTL `$readmemh`
  初始化（综合为 ERAM/BRAM）。指标：VAL 联合 macro-F1 89.81%，BCCD 定位召回 100%。

### 3.2 RTL 加速器（yolo/ 目录）

| 模块 | 职责 | 要点 |
|---|---|---|
| `yolo160_first` | 输入采样+首层 | **无整帧 RAM**：全帧 1280×720 流上按固定模式抽 160×160（每 8 列取 1、隔 4/5 行取 1），仅 4 行×160×24bit 行缓存；3×3 W8 卷积 8 通道+pool2 |
| `yolo160_core` | 折叠层 1..9 | 4 lane/拍；隐层 **W4A4**(0..15)、头 W8/sat16；24bit 有符号累加；per-channel bias+shift requant（meta.hex 40bit/项） |
| `yolo160_boxes` | 后处理 | 256 项 LUT sigmoid、定点解码、top20 候选、贪心类别无关 NMS；输出 5 框×48bit+3bit 类别 |

- **量化位宽**：首层 W8/A8 → requant A4；阈值固化于 `yolo160_threshold.vh`
  （score=52020/65025≈0.80，NMS IoU≈0.4，objectness-only 打分）。
- **15Hz 分时**：顶层 `#(.FRAME_INTERVAL(2))`——每两帧推理一次，30fps 视频
  不间断；推理期间跳过的帧沿用上次结果；看门狗 6e6 拍 + cfg/帧号失配即 abort。
- **跟踪**（`cvp_yolo_tracks`）：类别绑定 + 几何唯一匹配（MATCH_DIST=96），
  漏检保持 2 次、第 3 次撤框（TTL=5，SINGLE_TARGET=1）——短漏检不掉框。
- **文字叠加**（`cvp_cell_label`）：5×7 点阵字模 function（28 字符 case 硬编码，
  非 ROM），框左上角绘英文全称；**SW1 按键开关**（延续 detect-integration 时期
  的消抖开关设计）。

## 4. 网络通路

| 通道 | 方向 | 内容 |
|---|---|---|
| UDP 6000 | 板→PC | 视频流：1920 包/帧@30fps ≈ 697Mbps，应用头 6 字节带偏移 |
| UDP 6001 | PC→板 | 相机参数命令（曝光/AWB/增益/Kelvin，`cvp_cmd_rx` 解码为寄存器写） |
| UDP 6002 | 板→PC | 状态包（flags/统计） |
| ETHB | 板→子板 | 6000 的发送镜像（`cvp_gmii_mac_tx` 双出） |

## 5. 子板 HDMI（hardware/hdmi/，EG4D20，TD 5.6）

数据通路：RGMII（PLL2 CPHASE 控采样相位+IDDR）→ 异步 FIFO → MAC/IP/UDP 栈 →
`cvp_rx_assemble` 帧重组（缺口≤4 包白名单放行+冻结延展填充，更大缺口跟踪-丢弃）
→ `uidbuf` 三缓冲+FDMA → DDR1 → VTC → 安路 logo OSD → TMDS/LVDS 720p60。

- 三缓冲写 30fps/读 60Hz 异步；事务级 DDR 仲裁仿真（含 2ms 总线黑窗注入）验证。
- 已知问题：RGMII 采样相位随电源漂移致偶发丢包（LED2=crc_bad 诊断），可盲扫 CPHASE。
- 资源：LUT 7556/19600（38.9%）、BRAM 44/64、PLL 4/4（门级）。

## 6. 时钟域与复位

| 时钟 | 来源 | 用途 |
|---|---|---|
| S_100m_clk | u_PLL clk0 | **主域**：ISP/检测推理/跟踪/标签/pack/发送组包 |
| S_24m_clk | u_PLL clk1 | 传感器 I2C 配置（uics500/u_uicfgcs500） |
| ~40.2M CSI 字节域 | MIPI DPHY RX | CSI 解包/uial2axis/line_retimer；`group_fifo` 跨入 100M |
| S_gmii_125m | pll_gmii125 | GMII/RGMII 发送；`cvp_cmd_rx` 另用 RGMII RX 裸时钟 |

复位：`S_rst_n = S_pll_lock`（PLL 自锁释放，**用户复位键不复位 PLL**——按键
R10 已改作 SW1 检测开关，PLL reset 引脚写 0）。跨域仅存在于 group_fifo 与
以太网收发两处，SDC 显式时钟组约束。

## 9. 版本沿革与 detect 链的定位

- **v27-v29（detect 链主线时代）**：AWB v2/边缘素描/相机启动门；v29 基座优化
  （直方图 LUTRAM、状态 ERAM 桥、FF −23%）。
- **v30**：裁掉本地 DDR/DSI 显示支路（Slice 70.73%→49.60%，PLL 4→2），保留 ETHB
  镜像——为后续检测器腾地的关键一步。
- **v31-v38**：视频平台打磨（中值/对比度、曝光 PID 分段/数字增益/高光保护、
  流健康恢复）。**v38 + detect-integration**：单类别（白细胞）CCL 检测链
  （color_feat→cid_filter→open3→wbc20）+ 像素烤框 + SW1 开关，板上验收通过，
  gate 16,497 片（77.76%）、Setup +109ps。
- **v2026.10.21（当前）**：识别主线**由 WBCAtt+ YOLO-style 接管**——从"检出
  白细胞"升级为"检测+五分类"。detect 链 RTL 完整保留于
  `hardware/mainboard/user_source/hdl_source/detect/`（顶层零例化，模块内回归
  与 TB 可复跑），其架构记录见 `docs/README_000_v4` 与 `docs/README_1017`；
  SW1 按键开关设计被新标签模块延续。历史 bit 归档 `old/releases/v38-candidate/`。

## 10. 已知边界

1. 空场景误检 1.76%/0.78%，未达原 1% 门槛（工程试验版定位）；
2. 精度数字非独立盲测（TEST 参与过前期实验）；
3. 单目标显示（SINGLE_TARGET=1）——多细胞同框时只保留一个；
4. 主板 89.6% slice，后续加逻辑余量很小；LeNet 片上分类方案因此被
   YOLO 五分类替代，`old/cellnet32/` 与早期分类原型全部退役；
5. 子板偶发丢包根因（RGMII 相位漂移）未根治，仅有缓解与诊断手段；
6. 复位键已改作检测开关：系统异常只能断电重启（Flash 固化后自动恢复）。
